## Demonstrated cause and repair

The previous `bindMeshyPilot` replaces only six standing trees inside x[-65,32], z[-140,-90]. Most of the 913 persistent world tree anchors and the woodland, farm and ruin-site trees still use generated branch/canopy displays. The original assets contain 10,334 pine triangles and 10,302 broadleaf triangles; directly repeating those throughout the world would be unnecessarily expensive.

The existing, locally installed meshoptimizer creates two geometry-only derivative GLBs from those exact original Meshy exports. The source files, painted atlases and normal maps stay byte-identical. No software is installed, no service is used and no new texture is downloaded. Original vertex positions, normals and UV values are retained through index reduction/remapping, with root contacts and extrema locked. Final-candidate near pine/broadleaf have 3,371/6,568 triangles; static outer-world pine/broadleaf have 3,327/6,552. The two derivative files total 1,195,520 bytes. Source hashes, generator/tool identities and normalization are embedded in the files. A second generation using the recorded defaults produced exact byte-identical derivatives (359,456-byte pine and 836,064-byte broadleaf); its CPU verification passed. These are static regional detail classes, not camera-distance LOD transitions.

Rounds 1 and 2 exposed folded crowns and brown/dark bands. A diagnostic isolated browser substituted original Meshy topology at the same paused camera: that removed the defect; additionally disabling normal detail made little difference. These diagnostic images are explicitly not native-motion or final performance evidence. CPU topology analysis showed 72.92% of R2 near pine and 85.39% of near broadleaf triangles crossed original position-plus-UV-connected charts; original and seam-preserving versions have zero. Round 3 therefore disables permissive seam collapse for both regional classes. The former 220KB/1,800-near-triangle limit was a builder-selected target, not an owner requirement; it was revised to a 1.25MB/7,000-triangle bound after this demonstrated defect. An intermediate near-only fix was not selected, because static outer-world trees can also be approached by the camera. Failed intermediate checks and captures remain recorded, never substituted into final evidence.

The existing spatial partitioner now also handles imported tree batches with at least 32 instances. Other batches retain their previous threshold of 256. This matters because the conversion changes each tree from many small display pieces to one larger mesh; using the old threshold would leave entire broadleaf regions submitted together. This is render storage/culling only. The same original canonical instance IDs continue to drive destruction and restoration.

`treeBatches.finish(records)` converts all remaining standing `windRoot` groups using those shared Meshy masters. It covers near and distant world trees, unregistered/protected decorative roots and resource-local trees. It retains rootless shrubs, log piles and attached ground dressing. Canonical owner ranges are repaired after compacting only the removed standing display parts. The original record IDs, coordinates, sizes and collision rules remain unchanged. The previous six pilot trees keep their exact full-detail geometry, materials and placement; pilot rocks are untouched. Pine batch names retain the existing debris-species suffix.

Both new LOD files are mandatory during ordinary startup and share the original atlas materials; asset failure rejects startup instead of silently drawing old standing trees. CPU-only construction fixtures can still intentionally omit loading. Instancing, existing spatial partitioning and the original vegetation clock provide batching, culling and motion. There is no runtime simplification, additional texture or per-tree JavaScript animation. The compact proportion limit stays within each original maximum display envelope; it does not move a tree root or alter collision radius.
